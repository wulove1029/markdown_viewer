## 步驟 4：結果定位與待復原只讀頁

主線擴充本分工所有權至 `app/renderer.py`，新增兩個 API：

- `reveal_source_line_after_load(line_number)`：接受一基來源行號，等待對應 render generation 完成，或在已完成的文件立即安排定位。由 `data-src-start/end` 找最小包含該行的可見區塊；這是來源區塊定位，不是選取字元或段落內精確視覺行。
- `show_pending_recovery(path)`：顯示只讀待復原提示及來源檔名，不提供首頁導航、不載入文件或替換草稿。

真實 WebEngine 驗證發現兩件需要處理的事：本機 PySide `findText` 不接受 `resultCallback` 關鍵字，改用位置參數；Chromium 原生尋找會在結果回呼後才捲動，因此來源定位會取消原生尋找，再於下一畫格定位。這會清除原生搜尋高亮，避免定位後又被拉回第一個同字匹配。新的搜尋、目錄跳轉或 render generation 會取消舊來源定位。

```powershell
$env:RUN_WEBENGINE_TESTS='1'
$env:QT_QPA_PLATFORM='offscreen'
$env:QTWEBENGINE_CHROMIUM_FLAGS='--disable-gpu'
py -3 -X utf8 -m pytest tests/test_renderer_source_navigation.py tests/test_renderer_async.py -q -p no:cacheprovider
```

最終實跑 exit code 0：`10 passed in 1.20s`，包括 3 個真實 WebEngine 案例：100 段相同關鍵字文件指定後段來源區塊、最小包含區塊與 generation 防護、待復原只讀頁無首頁導航。另有等待／取消／舊 find 回呼的回歸檢查。
