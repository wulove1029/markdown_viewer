# Markdown Viewer 完整升級優化計畫

日期：2026-10-22（Asia/Taipei）  
評估基準：本機 commit `47f6b47`、應用程式 `1.35.0`。  
交付範圍：產品與技術規劃、介面概念；本次不修改應用程式功能。

## 1. 產品方向與決策摘要

把本專案提升成「打開就能讀、隨時能寫、找資料快、切換不中斷」的 Windows 文件工作區。閱讀、寫作與介面提升列為同等重要的產品工作，效能和資料安全貫穿所有階段。

建議採取以下方向：

1. **閱讀優先的工作區**：內容佔主要畫面，文件庫、大綱、註記按需展開。
2. **寫作有一致的操作規則**：來源與 Office 共用命令、文件狀態與保存契約，切換保留位置和未存內容。
3. **介面有清楚層級**：常用操作留在眼前，進階功能透過情境工具列、選單與命令搜尋取得。
4. **以使用者感受到的時間驗收**：輸入反應、內容出現、搜尋首批結果與切換完成分開量測。
5. **逐批改善既有架構**：沿用 PySide6、既有渲染與保存機制；大型架構替換需另有性能及維護收益證據。

建議先完成「介面基礎＋閱讀預設＋編輯一致性＋性能基線」，再投入索引與長文深層優化。不要讓整份計畫成為必須一次完工才能使用的大改版。

## 3. 介面提升：推薦版面與替代方向

### 推薦：精簡工具列，內容為主

- **頂部主列**：側欄、新增／開啟、文件名稱、儲存狀態、工作模式、搜尋、更多。已儲存／未儲存／儲存中／失敗有明確文字與圖示。
- **文件分頁列**：固定位置；顯示 dirty、固定分頁、完整路徑提示。大量分頁用列表尋找，避免名稱全被擠掉。
- **左側導覽**：文件庫、搜尋、最近／收藏；標籤與關聯資料保留在清楚的次層入口。記住面板寬度與所選文件庫。
- **中央內容**：閱讀與寫作保持相近的內容寬度及起始位置，降低模式切換後重新找段落的成本。
- **右側內容工具**：大綱、註記、屬性依情境切換；預設收合低頻工具，支援一鍵釘選。
- **底部狀態列**：閱讀顯示章節／進度；寫作顯示字數／選取字數／游標位置；PDF 顯示頁碼／縮放。把低頻診斷移入獨立入口。

對外模式建議為「閱讀／寫作／並排」；「寫作」裡清楚標示 Markdown 或 Office。這是介面提案，實作初期保留現有模式和快捷鍵對應，避免修改既有持久化語意。PDF 使用適合 PDF 的工具與狀態。

| 方向 | 優點 | 取捨與建議 |
|---|---|---|
| 精簡工具列 | 內容空間大、長時間閱讀與寫作較安定 | 進階指令要有好找的選單及命令入口；推薦預設 |
| 保留功能區 | 既有使用者熟悉、格式工具容易探索 | 佔用垂直空間；作為可切換版面保留 |
| 專注模式 | 最大化本文空間，適合深讀與長文寫作 | 明確提供退出與暫時喚出導覽；作為前兩種的附加狀態 |

介面概念見 [工作區概念](2026-10-22-workspace-concept.html)。這是提案示意，不是目前產品畫面，也不是已完成的 PySide6 功能。

### 視覺與互動規格

- 建立一份設計規格：字級、間距、邊框、圓角、圖示、焦點、選取及狀態色；Qt、閱讀 WebEngine 與 Office 共用語意。
- 初始建議值：UI 10–11 pt、本文 17–19 CSS px、行高 1.65–1.8、中文每行約 34–42 個全形字；保留緊湊與寬鬆預設。這些是待驗證設計值，使用者可調整。
- 字體採 Windows 可用的繁中文字型 fallback；來源編輯使用等寬字型搭配中文字形。避免把整個畫面縮放當作唯一字級調整方式。
- 深色主題保持層次、表格分隔、程式碼及註記可辨識；新增暖色閱讀主題。選取與未存狀態同時用文字／圖示表達。
- 載入延遲超過約 150 ms 才出現輕量提示；超過約 1 秒顯示原因與可用動作。切換時立即顯示正確文件身份，過期內容不能冒充新文件。
- 動畫只服務導覽與狀態變化，控制於約 100–150 ms，支援減少動態效果；不把動畫加入輸入熱路徑。
- 100%／125%／150%／200% DPI、窄視窗及雙螢幕驗證；主要操作可用鍵盤完成，Tab 順序、焦點框、tooltip、accessible name 一致。
- 本文對比以 4.5:1、主要非文字控制與焦點以 3:1 作為設計驗收目標；這不等於宣告整個桌面軟體取得無障礙合規認證。

### 介面驗收

以 5 位代表使用者做首輪形成性測試，執行開檔、搜尋後返回、切換編輯、插入表格、儲存、找回草稿六項任務。記錄完成率、耗時、誤觸與求助；目標至少 90% 任務無協助完成，常用流程中位耗時比改版前降低 20%。此樣本用於發現問題，不視為統計上的全面證明。

## 4. 閱讀體驗升級

| 項目 | 行為設計 | 驗收 |
|---|---|---|
| 閱讀預設 | 整合字體、字級、行高、行寬、段落距離、主題，提供舒適／緊湊／寬版三組可調預設 | H1–H6、中英混排、長 URL、表格、公式、程式碼都不破版；設定跨重啟保留 |
| 專注與章節導覽 | 專注隱藏非必要工具；大綱追蹤當前章節、上一／下一章節、導覽返回 | 選取文字或使用滑鼠時不自動搶焦點；可一鍵返回先前閱讀位置 |
| 位置穩定 | 延續既有閱讀還原，加入標題／區塊錨點與偏移 fallback | 圖片與圖表晚到、換主題／字級、切分頁後仍停在同段；內容變更時安全回退 |
| 圖表與媒體 | 圖片放大／符合寬度、寬表與程式碼各自水平捲動、圖表按需展開 | 本文不被超寬內容撐開；大型圖表不阻塞第一屏 |
| 註記與研究 | 篩選註記、回到原文、複製含來源摘錄、整理成 Markdown 筆記 | 保留原檔與 sidecar 契約；匯出摘錄包含文件及段落／頁碼；失效錨點明示 |

閱讀體驗不只追求更少按鈕；需要保留查找、定位、比較與標註的效率。

## 5. 編輯與寫作升級

### 第一優先：寫得安心、切換可信

1. **統一命令路由**：格式、範本、附件、搜尋取代、儲存與匯出，都由同一入口派往目前編輯後端；後端不支援時明確提供來源編輯替代。靜態檢查發現範本入口與一般格式入口的 Office 防護不同，列為待重現項目，尚不認定為已確認 bug。
2. **繁中輸入列為發布條件**：Microsoft 注音、倉頡／速成，涵蓋組字中 Enter、Esc、方向鍵、候選選字、切分頁、儲存、焦點變更。智慧括號與 slash 選單不能攔截候選字操作。
3. **保存真值契約**：延續分頁 QTextDocument 為保存真值，Office 在保存、匯出、換頁、關閉前取得 live snapshot；錯誤與逾時可重試且不能回存舊內容。
4. **語法往返保真**：front matter、Wiki-link、callout、參照連結、表格、數學與 Mermaid 用 corpus 驗證；保留既有 Office 相容性警告與來源編輯建議。
5. **外部修改與復原**：衝突畫面並列本地／磁碟內容，清楚提供保留、另存與重載；草稿狀態和是否真正保存分開顯示。

### 第二優先：長文寫作效率

- **專注寫作／打字機捲動**：可選目前段落聚焦，游標保持在視窗中段；選取、搜尋及跳標題期間暫停自動追蹤。
- **大綱編輯**：先提供跳轉、折疊與調整標題階層；章節拖曳排序後續加入，需處理圍欄、清單、錨點與 Undo。
- **並排同步**：從百分比同步升級為來源行／渲染區塊對應，尤其是長圖、表格、公式造成兩邊高度差時。
- **草稿與範本**：加入可復原的未命名草稿、最近範本、範本預覽；第一次儲存才選路徑，仍顯示尚未寫入正式文件。
- **格式與資料輸入**：補齊來源／Office 的表格、連結、圖片與清單操作一致性，優先改善已有入口；貼上表格與附件時提供適當預覽。
- **命令搜尋**：提供文件操作與格式命令搜尋及最近使用；現有 Ctrl+Shift+P 已是 PDF 匯出，不直接覆蓋，新增可設定快捷鍵。
- **字數與寫作狀態**：已有中英混合統計，改成增量或低優先更新；進度目標為可選功能，不在預設介面增加干擾。

核心驗收：100 KB／1 MB 文件，連續繁中輸入、Undo／Redo、貼上與後端切換；與預期文字逐字一致，沒有重複、遺字、錯游標與保存舊快照。測試應分清同後端 Undo 保持、跨後端切換的既有行為與任何擬新增契約。

## 6. 效能與架構計畫

以下是靜態程式碼推論的優先候選，需 profile 後再決定具體實作；不宣稱都已被證明為當前最大瓶頸。

| 工作 | 現況與方案 | 優先度／關聯 |
|---|---|---|
| 輸入熱路徑 | 已有 debounce，字數與並排更新仍取全文；先做增量統計，再評估區塊預覽及超時降級 | P0；寫作 |
| 全文搜尋 | 每次查詢重新遍歷、解碼，結果一次建立大量 widget；改增量索引、首批結果、分批或 model/view 呈現 | P1；查找與長庫 |
| 中文搜尋 | 保留目前子字串語意；SQLite FTS5 可做候選，需驗證中文單字／雙字、符號與英文混排，短查詢設 fallback | 與索引一起完成 |
| 文件庫共享索引 | metadata、標籤與反向連結依文件版本做增量更新，合併重複掃描；索引可重建 | P1；與搜尋共用 |
| PDF 布局 | 分批尺寸已存在，每批後仍全量 relayout；量測後評估分塊布局／增量累積高度 | P1；保留混合紙張與原頁錨點 |
| 背景工作配額 | 現有取消與 generation guard 保留；增加全域優先級、併發上限、重複請求合併與過載背壓 | P1；可見內容優先 |
| 主執行緒 I/O | Properties 為下一 UI turn 同步讀取，大 HTML 準備亦有編碼／寫檔成本；改可取消背景準備與版本驗證 | P1；先追 trace |
| 大文件策略 | 冷高亮、圖表、完整 DOM 分階段；TXT 固定字數批次改時間預算；10 MB 以上 Markdown 提供清楚的受限閱讀／來源處理 | P1–P2；不能靜默截斷後儲存 |
| 記憶體管理 | 統計 Qt＋WebEngine＋worker 整個程序樹；預覽／索引受總預算約束，dirty 文件與 Undo 不可因回收丟棄 | P1；與速度共同驗收 |
| 架構整理 | 逐步抽出 document session、open coordinator、save/recovery service、command router，保留既有行為測試 | 隨各批改善；不先做大規模搬家 |

全文搜尋若採 FTS5，不能假設預設 tokenizer 就等於中文子字串搜尋。官方文件明示 trigram 以連續三字元建立 token；少於三字元（1–2 字元）的查詢需另設策略。[SQLite FTS5 官方文件](https://www.sqlite.org/fts5.html)

### 提議效能門檻

所有數字都是**待建立基線後確認的產品目標，目前未驗證達成**。以指定 Windows 11、SSD、16 GB RAM 測試機為初始參考，CPU／螢幕／電源模式／防毒／建置版本須寫入結果；低階機另列。

| 指標 | 提議目標 | 量測定義 |
|---|---|---|
| 啟動至可操作 | 暖啟動 P95 ≤1.5 s；冷啟動 P95 ≤3 s | 從已安裝 EXE 啟動到可接受命令；有文件再另量首屏 |
| 打字回應 | 100 KB 文件 P95 ≤50 ms；1 MB P95 ≤80 ms | 輸入／IME commit 到畫面呈現；組字與背景統計另追蹤 |
| Markdown 暖切換 | 100 KB 可讀 P95 ≤150 ms；探索 ≤100 ms | 相同 workload 保持歷史代理不退步，另補實體首幀 |
| 長文首屏 | 1 MB 複雜 MD P95 ≤500 ms | 首批正確可讀與完整完成時間分列，不能只給 loading 畫面 |
| PDF 返回原頁 | 3,000 頁 UI gap P95 ≤50 ms | 整個視窗另量可讀時間；元件 raster 不代替端到端 |
| 文件庫搜尋 | 10,000 份文件暖查詢首批 P95 ≤200 ms | 記錄總大小、命中數、中文短查詢；debounce 與查詢耗時分開並報端到端 |
| 工作區 UI 更新 | 每批背景結果套用目標 ≤8 ms | 以 trace 驗證，非固定插入 N 筆就視為達成 |
| 記憶體穩定 | 固定 10 文件工作集暖身後，100 次切換／關閉淨增 ≤10% | 連同子程序量測；先定穩態預算，不能把無限 cache 當成速度提升 |

效能試驗固定語料：10 KB／100 KB／1 MB／5 MB MD；長文、程式碼、表格、公式、圖表；5／50 MB TXT 與超長單行；100／1,000／3,000 頁混合尺寸 PDF；1,000／10,000 份文件庫。冷暖、來源碼／EXE、本地／慢磁碟／雲端占位檔分組。

暖操作每組至少 30 次、重要切換採 100 次並保留原始資料；冷啟動定義 OS cache／重開機條件，至少 10 次作初探，正式 P95 需增加樣本，不用 10 次初探宣稱穩定尾端表現。

## 7. 資料安全、可維護性與發布

- 延續原子保存、備份與 pending recovery，補「程序被強制終止」後復原，不只驗證同程序例外回滾。
- 檔案搬移若跨正文、sidecar、草稿與連結改寫，增加持久化交易紀錄與重啟回放；不覆寫來源或清理備份直到可恢復狀態確定。
- 外部修改偵測以版本驗證接到保存，涵蓋雲端同步、檔案消失、只讀、權限拒絕與磁碟滿。
- 版本資料與設定採可回退 migration；索引可丟棄重建，使用者內容不可當 cache 清理。
- UI 核心改動加入真實 WebEngine 的必要 CI job；Office 與 renderer 可分程序隔離，但已知逾時仍要定位，不以增加 timeout 取代修正。
- 減少 pyproject 既有檔案忽略規則、擴大有價值的型別檢查，隨模組變更逐步進行；不因追求行數而重構所有程式。
- 打包版驗收包含乾淨安裝、覆蓋升級、檔案關聯、單一實例、離線資源、更新失敗還原與實體 DPI／雙螢幕。
- 診斷預設本地保存耗時、工作數量、cache hit／fallback／cancel，不記錄文件全文；提供使用者可檢查的匯出。
